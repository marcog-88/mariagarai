## What this repo is
- Vite/React SPA serving **mariagarai.com** — María's public brand hub only: home, legal pages (`/legal`, `/privacy-policy`, `/terms-of-service`, `/cookie-policy`), and a 404 catch-all.
- The former program pages were retired in the 2026-09 hub-only cut. `/construye` and `/disena-tu-oferta` 301 to laexponencial.com (`/` and `/disena-tu-programa`, pointed straight at the final URLs on 2026-10-24); `/exponencial` and the old `/eventos` paths 301 there too. `/oferta-privada-construye` and `/redes-que-venden` were retired permanently — no redirect, they 404. All redirects live in `vercel.json`. Retired code is archived under `_archive/retired-2026-09/`.
- Routing (since 2026-10-24): there is no SPA catch-all rewrite. The build writes one static HTML file per route (`legal.html`, `links.html`, …) plus `404.html` from `src/seo/routes.ts`, each with its own title/description/canonical/robots; `cleanUrls` serves them and every other path gets a real HTTP 404. **A new route needs an entry in `src/seo/routes.ts`** as well as in `App.tsx`, or it will 404 on a hard load (the WhatsApp bubble's known-route list reads the same table).
- Prerendering (since 2026-10-24): `npm run build` = client build → SSR build of `src/entry-server.tsx` → `scripts/prerender.mjs`, which renders every route's React tree into its HTML file (so the h1 and body text are in the served HTML) and deletes `dist-ssr/`. `src/main.tsx` hydrates with `hydrateRoot`. Render must stay deterministic: no `window`/`document`/`Date`/`Math.random` outside effects, or hydration mismatches. `src/test/prerender.test.tsx` renders + hydrates every route and fails on a mismatch.
- SEO head (all in `vite.config.ts`): per-route meta from `src/seo/routes.ts`; the home's JSON-LD (`Person` + `Organization` La Exponencial + `WebSite`) from `src/seo/structuredData.ts`; `sitemap.xml` is generated from the indexable routes with `lastmod` = build date (there is no `public/sitemap.xml`).
- Search Console / Bing verification: set `VITE_GOOGLE_SITE_VERIFICATION` and/or `VITE_BING_SITE_VERIFICATION` (the token only, not the whole tag) in the Vercel project env (or `.env.local`); the build adds `google-site-verification` / `msvalidate.01` meta tags to every route HTML. Unset = no tag. See `.env.example`.
- Share image: `public/og-image.png` (1200×630) and the JSON-LD portrait `public/maria-garai.jpg` are generated by `npm run og-image` (`scripts/og-image.mjs`, satori + sharp, home palette and Instrument fonts). After regenerating, bump the `?v=` on `og:image` / `twitter:image` in `index.html`.
- The old `api/send-confirmation.js` Vercel serverless route (Resend confirmation emails, service-role key) was deleted in the same cut — this repo now has no server-side routes and needs no secret env vars. All student/platform/admin surfaces live in `marcog-88/exponencial`, not here.

## Repo-specific rules
1. **This repo goes stale silently.** María commits from her own machine. `git fetch origin` and compare local vs origin hashes BEFORE reading a single file, every session. Where a deployed page is the reference, diff against the live site too — the repo is not automatically what visitors see.
2. **María's deployed copy is verbatim.** Never apply house-style transforms to her page content. If a house rule and her source conflict, her source wins — flag it, don't transform silently.
3. **Color system is locked:** Homepage accent is purple `#9378fe`. CTA buttons use the page lead accent. Color overrides via scoped CSS variable block on the page wrapper only — never `src/index.css`, never global tokens, never other pages.
4. **Pricing format:** `€1997`, never `€1.997`. No decimal points anywhere.
5. **301 redirects to laexponencial.com** (old `/eventos`, lead magnet paths) are load-bearing — old links live in sent emails and LinkedIn/Substack posts. Never remove or break them.
6. **Vercel:** this project builds previews, but SSO protection blocks anonymous checks against preview URLs. Verify on production after merge.
7. Session flow: one branch per session off main, `git add` only named files, PR, merge, confirm merge commit on main. When in doubt, ask Marco.
